# Node and TypeScript checks

Find the package manager and its version from the `packageManager` field in `package.json` first, then from the lockfile: `package-lock.json` means npm, `pnpm-lock.yaml` means pnpm, `bun.lock*` means bun. With `yarn.lock`, check `yarn --version`: 1.x is Yarn Classic (`yarn install --frozen-lockfile`, `yarn audit`, `yarn outdated`), while 2+ is Berry (`yarn install --immutable`, `yarn npm audit`, and no built-in outdated, so use `npx npm-check-updates`). Install with the manager's frozen command (`npm ci`, `pnpm install --frozen-lockfile`, `bun install --frozen-lockfile`, or the yarn form above). Installing is allowed in the finder's worktree. Nothing else gets written.

- **node.lockfile**: Finding: no lockfile, or the frozen install fails because the lockfile doesn't match `package.json`. Severity: medium.
- **node.audit**: Run `npm audit --json --omit=dev` (pnpm and yarn have equivalents). Finding: high or critical advisories in production dependencies that have a fixed version. Group them into one ticket per repo and list the packages with the version that fixes each. Severity: high for critical, otherwise medium. Not a finding: dev-only advisories, or advisories without a fix. Mention those in the report.
- **node.outdated-major**: Run `npm outdated --json`. Finding: a direct dependency two or more majors behind, or one major behind when that major is EOL or the framework's docs mark it unsupported (Next, React, Vite, Astro, TypeScript, ESLint and similar). One ticket per framework-level package. Smaller libraries share one ticket. Severity: medium. Size: usually M or L, so say what the migration guide covers.
- **node.outdated-minor**: Finding: one rollup ticket per repo, filed only when more than 10 direct dependencies are behind on minor or patch versions. Severity: low. Never file single minor bumps.
- **node.runtime**: Compare `engines`, `.nvmrc`, `.node-version` or `mise.toml` with what CI uses. Finding: an EOL Node major (as of 2026-11, Node 20 and older are EOL; check endoflife.date when online), or local and CI disagreeing on the major. Severity: medium.
- **node.typecheck**: When `tsconfig.json` exists, run the typecheck script, or `npx tsc --noEmit` if there isn't one. Finding: type errors on the default branch. Severity: high when the build skips type checking and the errors are real, otherwise medium.
- **node.lint**: Run the lint script if one exists. Finding: errors, not warnings. Severity: low, or medium for rules that catch bugs (hooks rules, no-floating-promises).
- **node.unused**: Run `npx knip --no-progress` when knip is a dependency or the network is available. Finding: unused dependencies or unused exported files. Group into one ticket. Severity: low. Skip it when the tool reports more than 50 items, since that usually means a config problem. Mention it in the report instead.
- **node.scripts**: Judgment. Finding: a package script that references a missing file or tool, or a `postinstall` that downloads or runs remote code without pinning it. Severity: medium.
